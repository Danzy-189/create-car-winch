# Create: Tow & Haul

Аддон для **Create: Aeronautics / Create: Simulated** на NeoForge (Minecraft 1.21.1).

Сцепное оборудование для физической техники:

- **лебёдка** на редстоуне, которая реально наматывает и отпускает физический трос;
- **фаркоп**, за который цепляется трос;
- **сцепка**, которая соединяет два фаркопа жёстким валом из Create — получается дышло.

Трос — это тот же `ServerRopeStrand` из Simulated, что использует лебёдка из Aeronautics.
Сцепка — это физический констрейнт Sable между двумя саблевелами.

> `mod_id` остался `carwinch`, поэтому все блокстейты, модели, ключи перевода, рецепты и
> уже созданные миры продолжают работать. Поменялось только отображаемое название.

## Лебёдка и трос

1. Поставь **лебёдку** на технику, а **фаркоп** — на то, что собираешься тащить.
2. ПКМ **стальным тросом** по лебёдке, затем ПКМ по фаркопу. Выбранная точка подсвечивается,
   подходящие цели тоже, и рисуется линия-предпросмотр. Shift + ПКМ — отмена выбора.
3. Лебёдка переключается на модель с намотанным тросом, фаркоп — на модель с крюком, между
   ними появляется физический трос.
4. Ножницы (любой предмет из тега `destroys_rope` в Simulated) режут трос. Ломание одного из
   блоков делает то же. В обоих случаях выпадает **стальной трос**, а не ванильная верёвка.

Обычная верёвка не работает — выводится сообщение. Соединять тросом можно только лебёдку с
фаркопом: два фаркопа тросом не связываются, для этого есть сцепка.

### Управление редстоуном

Лебёдка читает верх и низ отдельно, так что один блок умеет и тянуть, и отпускать:

| Сигнал | Поведение |
| --- | --- |
| **Сверху** (или с любой стороны) | Наматывает трос. Сила сигнала задаёт скорость. |
| **Снизу** | Отпускает трос под тягой. Сила сигнала задаёт скорость. |
| Оба сигнала, одинаковой силы | **Тормоз** — длина троса фиксируется. |
| Нет сигнала | Свободный ход — когда трос натягивается, лебёдка его травит, и можно уехать. |

Константы настройки — в `CarWinchBlockEntity`: `MAX_RANGE`, `REEL_SPEED`, `RELEASE_SPEED`,
`PAYOUT_SPEED`, `SLACK_TOLERANCE`.

## Сцепка: жёсткий вал из Create

Два фаркопа можно соединить **жёстким горизонтальным валом** вместо троса.

1. Поставь технику так, чтобы фаркопы смотрели друг на друга, **не дальше 4 блоков**.
2. ПКМ **сцепкой** сначала по фаркопу **ведущей машины**, затем по фаркопу **прицепа**.
   Первый клик — сторона шара. Между точками рисуется `create:shaft` одноблочными сегментами.
3. **Гаечный ключ Create** по любому из фаркопов разбирает сцепку. Ключом же блок
   поворачивается, когда сцепки нет.

Физика:

- Длина **замеряется в момент клика** и дальше держится жёстко (`couplingLength`, максимум
  `MAX_COUPLING_LENGTH = 4.0`, минимум `MIN_COUPLING_LENGTH = 0.05`). Ничего не телепортируется в
  момент создания, и вал потом не растягивается.
- Фреймы и якоря берутся из `FACING` самих блоков, а не из направления, в котором ты стоял
  при сцеплении. Поэтому вал сам выравнивается по фаркопам, а не застывает в той позе, в
  которой его создали.
- Разница высот двух фаркопов **запекается в якорь** (`couplingHeightOffset`, до
  `MAX_VERTICAL_OFFSET = 1.5`), а не оставляется солверу. Иначе солвер начинает поднимать тела,
  и колёса отрываются от земли.
- Констрейнт блокирует **только** `LINEAR_X/Y/Z`. Все три угловые оси свободны, и никаких
  `setLimit` нет — это чистый шаровой шарнир: прицеп поворачивает, кивает на пригорках и
  крутится вокруг своей оси на 360 градусов, не таща за собой ориентацию тягача. Любая
  заблокированная угловая ось сшивает повороты двух саблевелов: на уклоне одна машина
  поднимает колёса другой, а в повороте появляется опрокидывающий момент.
- Оба фаркопа должны стоять на **разных** собранных конструкциях.
- Сцепка сохраняется в NBT (`CouplingTarget`, `CouplingOwner`, `CouplingLength`, `CouplingHeight`).
  Если констрейнт стал невалидным (перезагрузка чанков, пересборка конструкции), он
  пересоздаётся — с кулдауном между попытками и лимитом попыток. Отдельный вотчдог рвёт
  сцепку, если тела оказались невозможно далеко друг от друга, так что сломанный констрейнт
  больше не может запустить саблевел через весь мир.

На любой отказ выводится причина: слишком далеко, слишком близко, не горизонтально, не на
конструкции, одна и та же конструкция или физика отказала.

## Модели и текстуры

- Фаркоп использует геометрию `rope_connector` из Simulated, поставленную вертикально.
- Трос рисует свой рендерер из частичных моделей `knot` и `rope`, которые ссылаются на
  текстуры `create:industrial_iron_block` — трос выглядит металлическим, а не пеньковым.
- Самой сцепке модель не нужна — это вал Create, отрисованный через
  `CachedBuffers.block(KINETIC_BLOCK, state)`. Важно: `renderSingleBlock` для кинетических блоков
  Create не рисует ничего, поэтому используется именно кешированный буфер.

Если хочешь заменить модели блоков, экспортируй из Blockbench через **File -> Export ->
Block/Item Model** по этим путям:

| Файл Blockbench | Куда экспортировать |
| --- | --- |
| `winch.bbmodel`   | `src/main/resources/assets/carwinch/models/block/winch.json` |
| `winch_1.bbmodel` | `src/main/resources/assets/carwinch/models/block/winch_1.json` |
| `towbar.bbmodel`  | `src/main/resources/assets/carwinch/models/block/towbar.json` |
| `towbar_1.bbmodel`| `src/main/resources/assets/carwinch/models/block/towbar_1.json` |

Варианты с `_1` — состояния *с крюком* / *с намотанным тросом*. `tools/import_models.sh`
предупреждает, если вариант байт-в-байт совпадает с базовой моделью — тогда смена состояния
в игре не видна. Модели рисуются направленными **вверх**; `blockstates/winch.json` и
`blockstates/towbar.json` поворачивают их для остальных пяти направлений.

## Сборка jar

### Вариант A — GitHub Actions (без локальной настройки)

`.github/workflows/build.yml` собирает мод на каждый пуш в `main` и по ручному запуску, а затем
выкладывает `build/libs/carwinch-1.1.0.jar` как артефакт.

### Вариант B — локально

Нужны JDK 21 и интернет (Gradle тянет Create, Sable, Veil, Flywheel и сборку
Сreate: Aeronautics с Maven/Modrinth).

```bash
gradle wrapper --gradle-version 8.12   # один раз, если Gradle установлен
./gradlew build
```

Результат: `build/libs/carwinch-1.1.0.jar`

`./gradlew runClient` запускает дев-клиент с Create и Aeronautics.

## Как подтягивается Simulated

Create: Aeronautics вложенным jar содержит модуль `simulated`, поэтому в `build.gradle` есть таск
`extractBundledMods`: он скачивает `maven.modrinth:create-aeronautics`, распаковывает
`META-INF/jarjar/*.jar` в `build/bundled-mods` и компилирует против них. Так гарантируется, что API
при компиляции и в рантайме один и тот же.

Если хочешь зафиксировать конкретную сборку — положи `simulated-*.jar` в `libs/`, эта папка тоже в
компиляционном класспасе.
